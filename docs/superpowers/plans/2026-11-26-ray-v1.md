# RAY v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compute Oren's frozen RAY v1 health score per site every evening from stored production history and Open-Meteo weather, store every component, and show it on the card and in the text once `RAY_VISIBLE` is on.

**Architecture:**
- Pure arithmetic lives in `rules/ray_math.py`.
- A `RayV1` calculator in `rules/ray_v1.py` plugs into the existing `RayCalculator` slot. It reads `daily_metrics` and the new `weather_daily` table, and writes the new `ray_daily` table.
- The evening pull fetches weather before the slot runs.
- History comes from an extension of the PR 1 backfill.
- Visibility is a separate setting from computation.

**Tech Stack:** Python 3.12, SQLAlchemy 2 on SQLite, httpx, APScheduler, Pillow + Raqm, pytest + respx. Tests: `.venv/bin/python -m pytest -q`.

**Spec:** `docs/superpowers/specs/2026-11-26-ray-v1-design.md`. Read it first. Where this plan and the spec disagree, the spec wins.

## Global Constraints

- The formula is exactly the spec's "The formula" block. Interpretations are exactly the spec's list, including 2b (the HistSub weights 2/3, 1/3 and 1/6 are applied as a weighted mean divided by the sum of the weights present). Each tunable value is a named module constant.
- Missing data is never zero. Only rows with `production_wh` not null and `comm_state` in (`ok`, `backfill`) count. If today's production or weather is missing, RAY is None.
- No SolarEdge credits for weather. Backfill costs at most 6 credits per site per calendar month, including PR 1's 2, all at priority `"optional"`.
- Open-Meteo errors and timeouts are logged by exception type only, never with URLs carrying coordinates at INFO level.
- `RAY_VISIBLE=false` (the default) means no RAY appears in any owner-facing output: card, text, answers or landing page.
- Customer copy never says "יעילות" or "Performance Ratio". The gauge caption is "מדד RAY".
- Every commit ends with the session's trailer lines (Co-Authored-By: Claude Opus 5.5 …; Claude-Session: …). Do not push.

## Review Focus

1. **Today's row not yet persisted when RAY runs.** `compute` must use the `actual_wh` passed in, not a DB read of today. Test in Task 4.
2. **A site with history only in one prior year, or with fewer than 10 real days.** The baseline falls back correctly to the other year or to the table. It never divides by zero, and an empty mean never raises. Test in Task 4.
3. **Open-Meteo returns hours in UTC, or with gaps.** The 07:00–16:00 window must use site-local hours: request `timezone=<site tz>` and select by the local hour. With fewer than 6 valid hours in the window, the value is None. Test in Task 2.
4. **`RAY_VISIBLE` false while RAY is computed.** Nothing leaks into the card, the text total line, answers or the landing page. Test in Task 5.
5. **Weighted overall when one site has RAY None.** It is left out. If all are None, there is no gauge. A zero-production day doesn't divide by zero. Test in Task 5.

### Task 1: RAY arithmetic and the national table

**Files:**
- Create: `src/solya/rules/ray_math.py`
- Modify: `src/solya/config.py`
- Test: `tests/test_ray_math.py`

**Interfaces:**
- Produces, in `ray_math.py`, all pure functions over floats and returning floats:
  - `clamp(x, lo=0.0, hi=100.0)`;
  - `perf_ratio(actual_wh, expected_wh, cloud_pct) -> float`: `min((actual/expected*100) / (1 - 0.3*cloud/100), 100)`, clamped at 0 or above;
  - `hist_sub(actual_wh, refs: list[tuple[float | None, float]]) -> float | None`, where `refs` holds (ref_wh or None, weight). Each present ref contributes `min(actual/ref*100, 100)`, and the result divides by the sum of the present weights. It returns None when no ref is present.
  - `health(cv: float | None) -> float`: `100 - min(20, cv/0.6*20)`, or 100 when `cv` is None;
  - `env(cloud_pct, tmax_c, pm10) -> float`: `100 - 40*cloud/100 - min(20, 0.4*max(0, tmax-25)) - 15*min(pm10/150, 1)`, clamped;
  - `perf(perf_ratio, hist_sub) -> float`: `0.7*pr + 0.3*(hist_sub if not None else pr)`;
  - `combine(perf, health, env) -> float`: `min(0.40*perf + 0.35*health + 0.25*env, perf + 25)`, clamped.
- Constants: `HIST_WEIGHTS = {"last30": 2/3, "year1": 1/3, "year2": 1/6}`, `MIN_BASELINE_DAYS = 10`, `MIN_LAST30_DAYS = 10`, `MIN_SAME_DAYS = 5`, `MIN_CV_DAYS = 10`, `WINDOW_HOURS = range(7, 17)`.
- `config.Settings` gains:
  - `ray_visible: bool = False`;
  - `ray_national_kwh_per_kwp_day: list[float]`, 12 values, validated as exactly 12 positive floats.

  The defaults come from PVGIS for lat 32.1, lon 34.8, optimal tilt, 14% losses. The builder fetches them from `https://re.jrc.ec.europa.eu/api/v5_2/PVcalc` with `peakpower=1&loss=14&optimalangles=1&outputformat=json`, using monthly `E_d`. If that is unreachable, the builder uses published PVGIS figures for central Israel. Record the source and date in a comment, with the old table `3.5, 4.5, 6.0, 7.5, 8.0, 7.2, 6.5, 6.5, 7.0, 7.5, 5.0, 3.5` beside it.

  - `combine(98.7, 92.0, 75.2) == pytest.approx(90.5, abs=0.05)`;
  - the cap binds: `combine(40, 100, 100) == 65`;
  - `perf_ratio(300_000, 300_000, 0) == 100`, and `perf_ratio(270_000, 300_000, 50) == 100` (90/0.85 ≈ 105.9, capped);
  - `hist_sub` with all three refs equal to actual is 100; with only `year1` and `year2` present, the division is by 1/3 + 1/6; with no refs present it is None;
  - `health(0.306)` ≈ 89.8, and `health(1.0) == 80`;
  - `env(0, 25, 0) == 100`, and `env(100, 80, 300) == 100 - 40 - 20 - 15`;
  - Settings rejects an 11-value table.

### Task 2: Open-Meteo weather and `weather_daily`

**Files:**
- Create: `src/solya/weather.py`
- Modify: `src/solya/models.py`, `src/solya/services/reporting.py` (`_pull_and_process`)
- Test: `tests/test_weather.py`

**Interfaces:**
- `models.WeatherDaily`, table `weather_daily`. Primary key (`site_id`, `local_date`). Columns: `cloud_pct` float, nullable; `tmax_c` float, nullable; `pm10` float, nullable; `source` str; `fetched_at`.
- `weather.WeatherDay` dataclass: `cloud_pct`, `tmax_c`, `pm10`, each `float | None`.
- `async weather.fetch_day(http: httpx.AsyncClient, lat, lon, tz: str, local_date: date) -> WeatherDay`. It makes two GETs, with a 10 s timeout:
  - forecast: `hourly=cloud_cover`, `daily=temperature_2m_max`;
  - air-quality: `hourly=pm10`.

  Both use `timezone=tz` and `start_date=end_date=local_date`. Each value is the mean over local hours 7–16 inclusive, None if fewer than 6 valid hours. `tmax` is the daily value. A failure of one call leaves only its fields None. It never raises for HTTP or parse errors.
- `weather.store_day(session, site_id, local_date, day, now)` upserts the row.
- In `Reporter._pull_and_process`: when `kind == "evening"`, `settings.ray_implementation` is set, and the site has `lat` and `lon`, fetch and store the day's weather before `_process` runs. Errors are logged by exception type.

**Interfaces:**
- `backfill.backfill_range(client, session_factory, site_id, start: date, end: date, now, *, with_export: bool) -> int`: the PR 1 logic generalised to any whole-month window. Its "tried" memory is a 200 `RawResponse` for `/sites/{id}/energy` whose stored `params["from"]` starts in the same month as `start`; the meter call is handled the same way.   - it writes only missing rows strictly before site-local today;

  - the previous calendar month (`with_export` per the site's basis);

  It only runs when `settings.ray_implementation` is set; the caller checks.
- `Reporter.backfill_soon(site_id)` runs the month backfill, then the history backfill when RAY is enabled.
- `SchedulerService` gains a monthly cron job at 01:00 local on day 1 that calls `backfill_soon` for every active, monitored site.

### Task 4: `RayV1` calculator and `ray_daily`

**Files:**
- Create: `src/solya/rules/ray_v1.py`
- Modify: `src/solya/rules/ray.py` (protocol, `load_ray`), `src/solya/rules/daily.py` (`compute_site_day` passes `actual_wh`), `src/solya/models.py`, `src/solya/app.py` (`load_ray` call)
- Test: `tests/test_ray_v1.py`, `tests/test_ray.py`

**Interfaces:**
- `RayCalculator.compute(site, local_date, session, actual_wh: float | None = None) -> float | None`. `NullRay` ignores `actual_wh`.
- `load_ray(path, settings=None)` instantiates `cls(settings)` when the class accepts one argument, otherwise `cls()`.
- `models.RayDaily`, table `ray_daily`. Primary key (`site_id`, `local_date`). Columns: `ray`, `perf`, `perf_ratio`, `hist_sub`, `health`, `env`, `expected_wh`, `expected_source` (`"history"` | `"table"`), `cv`, `cloud_pct`, `tmax_c`, `pm10`, `confidence` (`"normal"` | `"low"`), `computed_at`. All numbers are nullable floats.
- `RayV1(settings)` returns None when `session` is None, `actual_wh` is None, or the weather row or any of its three values is missing. Otherwise it computes and upserts a `ray_daily` row, then returns `ray`:
  - **Real days:** `daily_metrics` rows with `production_wh` not null and `comm_state` in (`ok`, `backfill`).
  - **Expected:** the mean of real days in the same calendar month one and two years earlier, with ≥ `MIN_BASELINE_DAYS` real days across them, as `"history"`. Otherwise `table[month-1] * kwp * 1000` Wh, as `"table"`, where kwp is `billing_kwp_override or peak_power_kwp_reported`. With no kwp, the result is None.
  - **HistSub refs:**
    - `last30` is the mean of real days in the 30 days before `local_date`, needing ≥ 10;
    - `year1` and `year2` are the means of real days from day 1 to the same day-of-month in that month one and two years ago, needing ≥ 5 each.
  - **CV:** population standard deviation divided by the mean, over real days in the 30 days before `local_date`, needing ≥ 10.
  - **Confidence** is `"low"` when the expected source is `"table"` or there are fewer than 30 real days in total.
  - It uses only `ray_math`.

- [ ] **Step 1: Write failing tests:**
  - With synthetic `daily_metrics` and `weather_daily` rows built so that Perf ≈ 99.8, Health ≈ 89.8 and Env ≈ 75.2, RAY is ≈ 90.2. Pick inputs that give these components, and document them in the test.
  - It uses `actual_wh` and never a DB row for today. A today row with different production must not change the result.
  - The baseline uses one year when the other year is missing, and the table when fewer than 10 days exist; `expected_source` and `confidence` are stored.
  - Stale rows (`comm_state="comm_loss"`) and None rows are excluded.
  - Missing weather gives None and writes no row.
  - With no kwp and no history, the result is None.
  - `load_ray("solya.rules.ray_v1:RayV1", settings)` returns a working instance.
