# Solya MVP 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single Python service that connects owners' SolarEdge sites over V2 OAuth, pulls and stores data on a credit-budgeted schedule, and sends the approved Hebrew evening card and text and fault/communication-loss alerts over Telegram. It runs on Oren's two real sites once a client ID, client secret and bot token are supplied.

**Architecture:** One asyncio process. uvicorn serves FastAPI (OAuth connect and callback). FastAPI's lifespan starts the python-telegram-bot application (long polling) and an APScheduler `AsyncIOScheduler`. Data flows one way:
- SolarEdge client → `raw_responses` + parsed models;
- pure rules → `daily_metrics` / `faults`;
- Hebrew text + PNG card → `Outbox` → `Channel` (Telegram).

Rules, text and card are pure functions with an injected clock. They never call the API.

**Tech Stack:**
- Python ≥3.12 (dev box 3.13);
- httpx, FastAPI + uvicorn;
- python-telegram-bot 22.x, APScheduler 3.10+;
- SQLAlchemy 2 (sync, SQLite);
- pydantic-settings, cryptography (Fernet);
- Pillow 13 with Raqm (needs `libfribidi0`), astral 3.2, tzdata;
- pytest, pytest-asyncio, respx, freezegun not needed (clock is injected).

**Spec:** `docs/superpowers/specs/2026-11-24-solya-mvp-design.md`. Reference material:
- `docs/reference/2026-11-24-recon-brief.md`;
- `docs/reference/solaredge/basic-monitoring-api.yaml` (the source of truth for V2 request and response shapes).

## Global Constraints

**SolarEdge**
- V2 only. Base `https://monitoringapi.solaredge.com/v2`. Never call V1 names (`details`, `energyDetails`, `currentPowerFlow`, `inventory`, `alerts?status=`).
- OAuth:
  - Authorize URL `https://connect.solaredge.com/authorize`.
  - Token `POST https://monitoringapi.solaredge.com/v2/oauth2/token` with a JSON body `{grant_type, code|refresh_token, client_id, client_secret}`.
  - Scope `SITE_DATA DEVICE_DATA`.
  - Data calls send `Authorization: Bearer <token>`.
- Time parameters are ISO-8601 UTC with `Z`. Day windows are local midnight→midnight in the site's `location.timezone`.
- `null` is unknown and never coerced to 0. Units are normalised case-insensitively (WH/KWH/MWH/GWH → Wh; W/KW/MW → W).

**Security and privacy**
- Never log or `repr` tokens or secrets. Never store owner passwords.
- `/sites/{id}` fields are allowlisted before storing or logging: `siteId, name, peakPower, lastUpdateTime, activationStatus, location.timezone, location.latitude, location.longitude`.

**Copy and naming**
- Text names come from `effective_label`: `label_he`, else `"המערכת"` for a single-site owner, else `portal_name`. The card uses `card_name` (default `portal_name`).
- The total label is `סה״כ`.
- The daily summary has nothing beyond the approved lines: no "system status", no forecast, no signature.
- Use "אין התראות פעילות", never "all healthy". Use "הכנסה", never "רווח".
- Hebrew RTL: every outbound text line starts with a Hebrew word. Every token that starts with a digit or Latin letter and follows Hebrew text on the same line is prefixed with RLM `‏`.
- Hebrew number formats:
  - kWh with 1 decimal, unit `קוט״ש`.
  - ₪ with 2 decimals, computed with `Decimal` ROUND_HALF_UP, written `142.65 ₪`.
  - Times `HH:MM` in site local time.

**Behaviour rules**
- Customer messages cannot trigger account actions. The only inbound side effects allowed are: issuing a connect link, registering via invite, and marking notified faults acknowledged.
- RAY is disabled by default (`RAY_IMPLEMENTATION` unset → `None`). When it is `None`, no RAY circle and no "RAY" word appear anywhere.

**Budget**
- Defaults: monthly cap 2000, billing anniversary day 1, per-minute limit 8, `max_credits_per_site_month` 350.
- Refuse `optional` calls at ≥90% of the cap and `essential` calls at 100%.

**Schedule**
- Evening pull at sunset + 25 min. Evening report at the owner's latest site sunset + 30 min.
- Mid-day check at `check_times` (default `["12:30"]`) for `commercial` sites only.
- Keep-alive token refresh if there has been no refresh in 7 days.
- Fault reminder after 3 h if not acknowledged.
- `commercial` defaults to `peak_power_kwp_reported >= 50`.

## Review Focus

1. **The overview fails or returns `production.total: null` while `lastUpdateTime` is fresh.** This covers 5xx, 429 and budget-refused calls. Expected:
   - The site line reads `{label}: המידע עדיין לא הגיע אלי, אני על זה.`
   - No figure and no total line appear.
   - One retry pull is scheduled 30 min later. If it succeeds, the full report is re-sent with a new `dedupe_key` suffix `:retry`.
   - Tests: Task 7 (`test_missing_overview_line`) and Task 12 (`test_retry_after_missing`).
2. **DST and day boundaries.** On 2026-10-25 (Israel DST end, a 25 h day), the overview window must be `2026-10-24T21:00:00Z` → `2026-10-25T22:00:00Z`. Test: Task 4 (`test_day_window_dst_end`).
3. **The owner blocked the bot.** Telegram raises `Forbidden`. Expected: the outbox records `blocked`, `owners.active=False`, other owners' reports still go out, and there are no retries. Tests: Task 9 (`test_blocked_marks_inactive`) and Task 12 (`test_one_owner_blocked_others_sent`).
4. **The process restarts after a report was sent but before the job is marked done.** There must be no duplicate report: the `dedupe_key` is `report:{owner_id}:{local_date}`. Test: Task 9 (`test_outbox_dedupe`).
5. **One of an owner's two sites is `reauth_needed`.** Expected:
   - The report still goes out with the other site.
   - The broken site's line is `{label}: החיבור ל־SolarEdge פג, שלחתי קישור לחיבור מחדש.`
   - There is no total line.
   - Tests: Task 7 (`test_reauth_line`) and Task 12 (`test_report_with_reauth_site`).

  - `async exchange_code(http: httpx.AsyncClient, settings, code: str) -> TokenPair`.
  - `async refresh_tokens(http, settings, refresh_token: str) -> TokenPair`. Both POST JSON to `{se_api_base}/oauth2/token`. Errors:
    - 400/401 with `error` in (`invalid_grant`, `invalid_request`) → `AuthExpired`;
    - other 400/401 (e.g. `invalid_client`) → `ApiError`;
    - 5xx or a timeout → `TransientAuthError`;
    - 429 → `RateLimited`.
  - `TokenManager(session_factory, settings, cipher, http, budget, clock, on_reauth_needed: Callable[[int], Awaitable[None]])`:
    - `store_new_grant(site_id, pair) -> None`. Sets `authorized_at=now` and `grant_expires_at = now + access_duration months`.
    - `async get_access_token(site_id) -> str`. There is one `asyncio.Lock` per site.
      - If the token expires more than 300 s after now, return the stored access token.
      - Otherwise call `budget.acquire(site_id,"oauth2/token","essential")`, then `refresh_tokens`, then `budget.record`.
      - In **one transaction**: `previous_refresh_enc = refresh_enc`, store the new access and refresh tokens, `access_expires_at = now + expires_in`, `refreshed_at = now`.
      - Return the new access token.
    - On `AuthExpired`:
      - If `previous_refresh_enc` exists and differs, retry once with it.
      - Otherwise set `Site.status="reauth_needed"`, await `on_reauth_needed(site_id)`, and re-raise `AuthExpired`.
      - Stored data is never deleted.
    - `TransientAuthError` propagates and the stored pair is left unchanged.
    - `async force_refresh(site_id) -> None` (keep-alive).
